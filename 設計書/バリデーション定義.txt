# バリデーション定義一覧

各画面における入力項目のバリデーションルールおよび業務ロジックによるチェック内容を以下に定義します。

## 1. 仕入画面 (T_仕入)
仕入情報の登録および在庫への反映を行う際のバリデーションです。

| 項目名 | 属性 | 基本ルール | 補足 |
| :--- | :--- | :--- | :--- |
| 発注日 | 必須 | 日付型 (YYYY/MM/DD) | デフォルトは当日 |
| ステータス | 必須 | プルダウン選択 | 「注文済み」「入庫済み」等 |
| 仕入先 | 必須 | 文字列 | 既存マスタにない場合はM_仕入先に自動登録 |
| 品名 | 必須 | 文字列 | 既存マスタにない場合はM_商品に自動登録（カテゴリ：パーツ/単体商品） |
| 価格 (合計) | 必須 | 数値 (0以上) | 全角入力時は半角に自動変換 |
| 数量 | 必須 | 数値 (1以上) | 全角入力時は半角に自動変換 |
| 支払方法 | 必須 | 文字列 | 既存マスタにない場合はM_支払に自動登録 |
| 区分 | 必須 | プルダウン選択 | パーツ、単体商品、梱包材など |
| 備考 | 任意 | 文字列 | 自由入力 |

---

## 2. 経費画面 (T_経費)
経費情報の登録および（梱包材等の場合の）在庫への反映を行う際のバリデーションです。

| 項目名 | 属性 | 基本ルール | 補足 |
| :--- | :--- | :--- | :--- |
| 日付 | 必須 | 日付型 (YYYY/MM/DD) | デフォルトは当日 |
| ステータス | 必須 | プルダウン選択 | 「注文済み」「完了」等 |
| 仕訳 | 必須 | 文字列 | 既存マスタにない場合はM_仕訳に自動登録 |
| 購入先 | 必須 | 文字列 | 既存マスタにない場合はM_仕入先に自動登録 |
| 品名・内容 | 必須 | 文字列 | 既存マスタにない場合はM_商品またはM_経費品名に自動登録 |
| 価格 (合計) | 必須 | 数値 (0以上) | |
| 数量 | 必須 | 数値 (1以上) | |
| 支払方法 | 必須 | 文字列 | 既存マスタにない場合はM_支払に自動登録 |
| 在庫管理対象 | 任意 | チェックボックス | ONの場合、M_商品（カテゴリ：経費）として在庫管理される |
| 備考 | 任意 | 文字列 | 詳細・メモ等 |

---

## 3. 製造画面 (T_製造)
製造開始時の部品引き当ておよび原価計算を行う際のバリデーションです。

| 項目名 | 属性 | 基本ルール | 補足 |
| :--- | :--- | :--- | :--- |
| 製造開始日 | 必須 | 日付型 (YYYY/MM/DD) | デフォルトは当日 |
| 製造数量 | 必須 | 数値 (1以上) | |
| 完成品名 | 必須 | プルダウン選択 | M_BOMに部品構成が定義されている商品のみ |
| 備考 | 任意 | 文字列 | 製造時の特記事項等 |

### 【業務バリデーション（在庫チェック）】
- **部品在庫不足チェック**:
    - 製造開始時、完成品の構成部品（M_BOM参照）が「製造数量 × 必要数」分、`T_在庫集計`に存在するか確認します。
    - **1つでも部品が不足している場合、エラーメッセージを表示し、登録処理を中断します。**

---

## 4. 販売画面 (T_販売)
販売登録および在庫からの自動引き当てを行う際のバリデーションです。

| 項目名 | 属性 | 基本ルール | 補足 |
| :--- | :--- | :--- | :--- |
| 販売開始日 | 必須 | 日付型 (YYYY/MM/DD) | デフォルトは当日 |
| 管理区分 | 必須 | 事業用 / 個人用 | ラジオボタン選択 |
| 売先 | 必須 | プルダウン選択 | 選択した売先に応じて手数料計算が行われる |
| 販売品名 | 必須 | 選択または入力 | 事業用：マスタから選択必須<br>個人用：自由入力可能 |
| 数量 | 必須 | 数値 (1以上) | |
| 販売価格 | 必須 | 数値 (0以上) | |
| 発送方法 | 必須 | プルダウン選択 | 選択時、対応する梱包材の在庫も1つ引き当てられる |
| 送料合計 | 任意 | 数値 (0以上) | |
| 送料負担 | 必須 | 出品者 / 落札者 | ラジオボタン選択 |
| 備考 | 任意 | 文字列 | PUDO位置や取引メモ等 |

### 【業務バリデーション（在庫チェック）】
- **商品在庫不足チェック**:
    - 取引開始時、販売品名の在庫が数量分、`T_在庫集計`に存在するか確認します。
    - 商品としての在庫が存在しない場合（かつ個人用での新規品名でない場合）、エラーを表示し中断します。
    - **履歴更新時の特例**: 履歴カードからの保存時は、既に引当済みであるため、この在庫不足チェックはスキップされます。
- **梱包材在庫不足チェック**:
    - 発送方法が選択されている場合、その発送方法名と一致する品名（梱包材）が在庫にあるか確認します。
    - 足りない場合はエラーを表示し中断します。

---

## 5. 在庫・棚卸画面
実在庫の調整を行う際のバリデーションです。

| 項目名 | 属性 | 基本ルール | 補足 |
| :--- | :--- | :--- | :--- |
| 実在庫 | 必須 | 数値 (0以上) | 棚卸モード時に入力 |
| 閾値 | 任意 | 数値 (0以上) | 通常モード時の在庫アラート設定値 |
| 備考 | 任意 | 文字列 | 棚卸確定時のメモ |

---

## 6. ステータス変更（履歴カード内）
履歴一覧からステータスを更新する際のバリデーションです。

- **日付の自動補完**: 
    - 特定のステータス（「入庫済み」「完了」「受取済み」等）に変更した際、対応する日付項目（入庫日、完了日、取引完了日等）が空であれば、操作日の日付を自動的にセットします。
- **排他制御**:
    - 更新処理中は「登録中...」と表示され、ボタンが非活性になります。
- **二重引当防止バリデーション (サーバーサイド)**:
    - サーバー側でのステータス遷移判定に加え、`T_在庫管理` の実レコード存在チェックにより、同一IDでの二重の在庫減算を物理的に遮断します。
- **購入予定から確定ステータスへの移行バリデーション**:
    - 仕入・経費が「購入予定」ステータスから他の確定ステータス（「注文済み」「入庫済み」「完了」等）に変更されて保存される際、通常時に必要なすべてのバリデーションルール（価格 > 0、数量 >= 1、仕入先・支払方法・区分等の必須入力）が適用され、不足がある場合は保存をブロックします。
- **履歴更新時の単価自動計算**:
    - 仕入履歴および経費履歴カードから「価格（合計金額）」および「数量」を更新（購入予定から確定ステータスへの移行に伴う新規数値入力を含む）して保存した際、バックエンドで「単価 = 価格 ÷ 数量」が自動的に再計算され、T_仕入およびT_経費シートの「単価」列にリアルタイムで上書き記録されます。
