### **# プルダウン・マスタ制御定義 **

**M_画面制御**シートは、システムの各画面における入力項目の挙動や、プルダウン・サジェストで参照するマスタデータを動的に制御するためのマスタです。

このシートのスキーマ（列構成）と各項目の役割は以下の通りです。

### **M_画面制御のスキーマ定義**

| 列位置 | 項目名 | 内容・役割 |
| :--- | :--- | :--- |
| **A列 (index 0)** | **対象機能** | 大まかな分類（仕入、販売、経費など）を指定します。 |
| **B列 (index 1)** | **画面名称** | 具体的なパネル名（新規仕入、進行中の仕入状況など）を指定します。 |
| **C列 (index 2)** | **要素ID** | **【最重要項目】** HTML側で定義されている `id` 名（buy-vendorなど）と紐付けます。 |
| **D列 (index 3)** | **画面上の項目名** | 画面に表示されるラベル名です。 |
| **E列 (index 4)** | **タイプ** | 項目の挙動を定義するキーワード（**select / suggest / fixed**）です。 |
| **F列 (index 5)** | **参照マスタ** | リスト表示に使用するデータの取得元マスタ名（M_商品など）を指定します。 |
| **G列 (index 6)** | **固定値の内容** | タイプが `fixed` の場合のみ、表示したい選択肢をカンマ区切りで記述します。 |
| **H列 (index 7)** | **説明** | 設定の意図などのメモを記述する備忘録欄です。 |

---

### **「タイプ」による挙動の違い**
システムのロジックはこの「タイプ」列を参照して、以下のように入力を制御します。

*   **select（選択専用）**: 既存のリストから選択するのみで、**手入力はできません**。主にステータスの選択などに使用されます。
*   **suggest（提案・自動追加）**: 入力候補を表示しますが、**リストにない新しい値の入力も許可**します。新規入力された名称は、登録時に該当マスタへ自動追加されるロジックが働きます。
*   **suggest-strict（制限付き提案）**: 入力候補を表示しますが、**リストにある値のみ許可**します。目的の項目を素早く探すための機能で、マスタにない値は登録時にエラーとなります。
*   **fixed（固定値）**: マスタシートを参照せず、G列に記載された**「固定値の内容」をそのまま選択肢として使用**します。

このスキーマ定義により、プログラム本体を修正することなく、スプレッドシート上の設定だけで iPhone 画面の入力補助を柔軟に変更できる設計となっています。

### **# 項目の挙動（タイプ）別処理ルール**

「挙動のルール」です。

*   **Type: select (選択専用)**
    *   UI: `<select>` タグを使用。
    *   Logic: 既存リスト以外の値は入力できない。
*   **Type: suggest (提案・自動追加)**
    *   UI: `<input list="...">` と `<datalist>` を使用。
    *   Logic: リストにない値を入力して登録した場合、GAS側の `verifyAndAddMaster` 関数により、該当するマスタシートの末尾へ自動的にその名称を追加する。
*   **Type: suggest-strict (制限付き提案)**
    *   UI: `<input list="...">` と `<datalist>` を使用（Type: suggestと同じUI）。
    *   Logic: 登録前にフロントエンドでバリデーションを行い、マスタに存在しない値の場合は登録をブロックする。
*   **Type: fixed (固定値)**
    *   UI: `<select>` タグを使用。
    *   Logic: マスタシートを参照せず、`M_画面制御` の「固定値の内容」列に記載されたカンマ区切りの値を使用する。


M_ステータスのスキーマ定義
列位置
項目名
内容・役割
A列 (index 0)
表示順
プルダウン内での表示順序を数値で指定します
。
B列 (index 1)
対象機能
「仕入」「販売」「経費」「製造」など、どの機能で使用するかを指定します
。
C列 (index 2)
画面名称
「新規仕入」「最近の経費」「製造中プロジェクト」など、具体的な画面（パネル）を指定します
。
D列 (index 3)
ステータス名称
画面のプルダウンに表示される実際の名称（例：注文済み、入庫済み、完了など）です
。
E列 (index 4)
役割（タイプ）
そのステータスが「進行中」なのか「完了」なのかといった、システム上の役割を定義します
。
F列 (index 5)
使用FLG
「1」が設定されているレコードのみがシステム上で有効な選択肢として読み込まれます
。

--------------------------------------------------------------------------------
主要な制御ロジック
システム側では、このスキーマに基づいて以下の制御を行います。
動的な抽出: 対象機能 と 画面名称 の2つの条件でフィルタリングを行い、その画面に最適なステータス候補のみを抽出します
。
ソート順: 抽出されたデータは、A列の 表示順 に基づいて昇順でソートされ、iPhone画面に表示されます
。
有効データの判定: 使用FLG が「1」または「TRUE」のデータのみが取得対象となります
。
この定義により、例えば「仕入」タブの「新規仕入」画面では「注文済み」や「入庫済み」を表示し、「製造」タブでは「製造開始」「テスト中」「完了」といった異なる選択肢を柔軟に表示させることが可能です
。

### **# マスタ取得時の共通バリデーション (GAS側)**
*   全ての名称リスト取得時、必ず **`使用FLG` 列（各シートの後方）を確認し、「1」のレコードのみを抽出**すること。
*   `M_ステータス` の取得時は、`対象機能` および `画面名称` の2条件でフィルタリングし、`表示順` でソートすること。
