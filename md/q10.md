 * マスタデータの汎用更新
 * 第一列をIDとして検索し、該当行のデータを更新する
 */
function updateMasterRecord(masterName, id, updates) {
  try {
    const sheet = SS.getSheetByName(masterName);
    if (!sheet) throw new Error("Master sheet not found: " + masterName);
    
    const data = sheet.getDataRange().getValues();
    const headers = data[0];
    const rowIndex = data.findIndex((row, idx) => idx > 0 && row[0].toString() == id.toString());

      if (colIdx !== -1) {
        sheet.getRange(rowIndex + 1, colIdx + 1).setValue(updates[key]);
      }
    }
    
    SpreadsheetApp.flush();
    return { status: 'success' };
  } catch (e) {
    return { status: 'error', message: e.toString() };

*   したがって、列を追加するだけで、GAS側で特別な修正をしなくても「無効」にした設定行はアプリに送られなくなります。

### 2. フロントエンド（Javascript）への影響
*   **動的UIの非表示**: `app.js`の`buildDynamicUI`関数は、`M_画面制御`から送られてきた設定に基づいてプルダウン（仕入先リストなど）を生成しています。
*   特定の行を「無効」にすると、その入力項目（SELECT要素など）の初期化処理がスキップされるため、その項目が機能しなくなったり、リストが空になったりします。
*   **検証**: 設定を無効にしても、HTML上の要素自体は残りますが、中身が「データ取得中...」のままになったり、デフォルト状態のままになったりします。

### 3. デグレード（動作不良）のリスク
*   **唯一のリスク点**: 運用中の重要な入力項目（例：販売品名の選択リストなど）の制御を誤って「無効」にしてしまった場合、その画面での入力ができなくなるという運用上のリスクがあります。
*   ただし、これは「設定モーダル」からいつでも「有効」に戻せるため、修正は容易です。

### 結論
影響範囲は「限定的かつ制御可能」です。マスタ管理の一貫性を持たせるためにも、**`使用FLG`列を追加することは良い選択**だと考えます。
